# Design Rules for AI — Landing Page

Правила та приклади, яких ші має дотримуватися при проєктуванні та верстці **лендінгу**: як будувати структуру, як розставляти акценти, як підбирати кольори й типографіку. Мета — цілісний, «нешаблонний» дизайн, що веде користувача до однієї дії.

> Формат: `✅ роби так` / `❌ не роби так`. Вимоги користувача (бренд, гайдлайн) завжди мають пріоритет над цими правилами.

---

## 0. Базові принципи

1. **Один лендінг — одна ціль.** Уся сторінка веде до однієї головної дії (CTA). Немає «цілі» — немає структури.
2. **Спершу визнач суб'єкт.** Що продаємо, кому, і яка одна робота сторінки. Дизайн виводимо з цього, а не з абстрактного «красиво».
3. **Сміливість витрачай в одному місці.** Один сигнатурний елемент, який запам'ятається; усе решта — тихе й дисципліноване.
4. **Ієрархія важливіша за декор.** Кожен елемент має явний рівень важливості; погляд рухається зверху вниз без конкуренції.
5. **Пробіл — це інструмент, а не порожнеча.** Повітря групує й розділяє блоки краще за лінії та рамки.
6. **Кожне рішення обґрунтуй.** Колір, шрифт, відступ — не «за замовчуванням», а тому що підходить саме цьому лендінгу.

---

## 1. Уникай «ші-шаблону»

Згенерований дизайн зараз тяжіє до трьох однакових виглядів — це «дефолти», а не рішення:

- ❌ Кремовий фон (~`#F4F1EA`) + контрастний serif + теракотовий акцент (~`#D97757`).
- ❌ Майже чорний фон + один кислотно-зелений/червоний акцент.
- ❌ «Газетний» лейаут: hairline-лінії, нульове заокруглення, щільні колонки.

Кожен із них доречний під конкретний бриф, але якщо напрям не заданий — **не витрачай свободу на дефолт**. Якщо бриф прямо просить такий вигляд — роби як просять.

**Правило:** перш ніж фіналити палітру/шрифт, спитай себе — «я прийшов би сюди для будь-якого іншого лендінгу?». Якщо так — перероби цю частину.

## 2. Структура лендінгу

Типовий кістяк (порядок і склад залежать від цілі):

```
┌─────────────────────────────────┐
│ NAV — лого + 2-4 пункти + CTA    │
├─────────────────────────────────┤
│ HERO — головна теза + суб-теза   │
│        + CTA + візуал/демо       │
├─────────────────────────────────┤
│ SOCIAL PROOF — логотипи/цифри    │
├─────────────────────────────────┤
│ VALUE — 3 блоки вигід/фіч        │
├─────────────────────────────────┤
│ HOW IT WORKS — 2-4 кроки         │
├─────────────────────────────────┤
│ TESTIMONIALS / кейси             │
├─────────────────────────────────┤
│ PRICING (якщо є)                 │
├─────────────────────────────────┤
│ FAQ                              │
├─────────────────────────────────┤
│ FINAL CTA — повтор головної дії  │
├─────────────────────────────────┤
│ FOOTER                           │
└─────────────────────────────────┘
```

**Hero — це теза.** Відкривай найхарактернішим у продукті: сильний заголовок, реальний скріншот/демо, інтерактивний момент.

✅ Добре:
> **Свіжі онігірі за передзамовленням у Львові.** Обираєш начинку сьогодні — привозимо завтра зранку. [Оформити замовлення]

❌ Погано (порожньо, ні про що):
> **Ласкаво просимо!** Ми — команда ентузіастів, що любить свою справу. [Дізнатися більше]

**Правила hero:**
- Заголовок каже, **що це і навіщо** — за 3 секунди зрозуміло.
- Один основний CTA, максимум один другорядний (наприклад «Дивитись демо»).
- Не пиши «Дізнатися більше» на головній кнопці — пиши конкретну дію.

---

## 3. Акценти та фокус

**Правило «одного акценту на екран».** На кожному екрані має бути один явний центр уваги. Якщо все виділене — не виділене ніщо.

Чим ставити акцент (за силою):
1. **Розмір** — головне більше за другорядне (заголовок vs текст).
2. **Колір** — акцентний колір лише на дії/ключовому елементі, не всюди.
3. **Контраст** — темне на світлому / насичене на приглушеному.
4. **Пробіл** — ізольований елемент читається як важливий.
5. **Позиція** — верх і центр = важливіше.

✅ CTA виділяється кольором і є єдиним таким елементом у секції:

```html
<a class="btn btn--primary">Оформити замовлення</a>   <!-- акцентний колір -->
<a class="btn btn--ghost">Подивитись меню</a>          <!-- нейтральний -->
```

❌ Не роби три яскраві кнопки поруч — користувач не знає, куди тиснути.

**Сигнатурний елемент.** Обери один елемент, який робить лендінг впізнаваним (нестандартна подача hero, унікальна ілюстрація, характерний патерн). Решту тримай спокійною, щоб він «звучав».

## 4. Кольори

### Як підбирати палітру

Опиши палітру як **4–6 іменованих hex**, з ролями:

```css
:root {
  --bg:        #0F1115;  /* фон */
  --surface:   #1A1D23;  /* картки, підняті поверхні */
  --text:      #E7E9EE;  /* основний текст */
  --muted:     #9AA0AB;  /* другорядний текст */
  --accent:    #FF7A45;  /* акцент — CTA, ключові акценти */
  --accent-2:  #3DDC97;  /* другорядний акцент, рідко */
}
```

### Правило 60 / 30 / 10

- **60%** — домінантний/нейтральний колір (фон).
- **30%** — вторинний (поверхні, блоки, текст).
- **10%** — акцент (CTA, важливі акценти). Акцент **рідкісний** — тому й працює.

❌ Якщо акцентного кольору більше ~10% — він перестає бути акцентом.

### Правила

- **Обмежена палітра.** 1 акцент + нейтральна база. Другий акцент — лише за потреби і дуже дозовано.
- **Ролі, а не «кольори».** Кожен колір має призначення (фон / текст / поверхня / акцент), а не «просто гарний».
- **Контраст тексту:** мінімум WCAG AA — 4.5:1 для звичайного тексту, 3:1 для великого. Перевіряй.
- **Акцент — тільки для дій і головного.** Не фарбуй ним увесь інтерфейс.
- **Похідні відтінки** генеруй від базового (світліше/темніше), а не бери випадкові.
- **Семантичні кольори** (успіх/помилка/попередження) окремо від бренд-акценту.

✅ Кнопка й hover виведені з одного акценту:

```css
.btn--primary        { background: var(--accent); color: #fff; }
.btn--primary:hover  { background: color-mix(in srgb, var(--accent) 85%, #000); }
```

❌ Не тримай 5 різних яскравих кольорів «щоб було весело» без системи.

## 5. Типографіка

**Пара шрифтів:** характерний **display** (заголовки, з обмеженим ужитком) + спокійний **body** (текст). За потреби — **utility** для підписів/даних.

```css
:root {
  --font-display: "Space Grotesk", system-ui, sans-serif; /* заголовки */
  --font-body:    "Inter", system-ui, sans-serif;         /* текст */
}
```

**Шкала розмірів** (приклад, modular scale):

```css
--step--1: 0.875rem;  /* дрібний текст */
--step-0:  1rem;      /* базовий body */
--step-1:  1.5rem;    /* h3 */
--step-2:  2.25rem;   /* h2 */
--step-3:  3.5rem;    /* h1 / hero */
```

**Правила:**
- Не більше 2–3 сімейств шрифтів на сторінку.
- Явна різниця між рівнями: h1 помітно більший за h2, той — за body.
- Довжина рядка тексту 50–75 символів (`max-width: ~65ch`).
- `line-height`: ~1.1–1.2 для великих заголовків, ~1.5–1.6 для body.
- Гра вагами (300/500/700) осмислена, а не випадкова.
- Не роби довгий body-текст усе капсом чи тонким світлим на світлому.

❌ Не став заголовок і текст одного розміру й ваги — зникає ієрархія.

---

## 6. Сітка, відступи, ритм

- **Система відступів** на базі 4/8px: `4, 8, 12, 16, 24, 32, 48, 64, 96`. Не «на око».
- Один вертикальний ритм між секціями (напр. `padding: 96px 0` на десктопі).
- Контент у контейнері з `max-width` (напр. `1200px`), з полями з боків.
- Групуй пов'язане ближче, розділяй незв'язане більшим пробілом (закон близькості).
- Вирівнювання: тримай спільну ліву межу/сітку, не «розкидай» блоки хаотично.

```css
.container { max-width: 1200px; margin-inline: auto; padding-inline: 24px; }
.section  { padding-block: 96px; }
```

---

## 7. Рух і мікровзаємодія

Анімація має **служити змісту**, а не бути присутньою «щоб було».

✅ Доречно:
- Плавна поява секцій при скролі (тонко, не «стрибками»).
- Hover-стан кнопок і карток (легке підняття/зміна кольору).
- Оркестрований момент на завантаженні hero (один, виразний).

❌ Зайве:
- Усе трясеться/вилітає з різних боків.
- Нескінченні паралакси й крутіння без причини.

**Обов'язково** поважай `prefers-reduced-motion`:

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

---

## 8. CTA та конверсія

- **Один головний CTA**, повторений угорі (hero) і внизу (final CTA).
- Текст кнопки = конкретна дія: `Оформити замовлення`, `Спробувати безкоштовно` — не `Надіслати`/`Тут`.
- CTA візуально найпомітніший елемент секції.
- Прибирай тертя біля дії: мінімум полів у формі, зрозуміло що буде далі.
- Соціальний доказ (цифри, відгуки, лого) — поруч із рішенням, а не наприкінці «для галочки».

---

## 9. Текст як матеріал дизайну

Слова — це теж дизайн, не декор.

- Пиши **з боку користувача**: називай речі так, як він їх сприймає, а не як влаштована система.
- Активний стан і конкретика: «Зберегти зміни», а не «Відправити».
- Одна назва дії через весь флоу: кнопка `Опублікувати` → тост `Опубліковано`.
- Порожні/помилкові стани — це напрям до дії, а не «вибачте, щось пішло не так» без деталей.
- Sentence case, без води, тон під аудиторію.

---

## 10. Адаптивність і якісний мінімум

- Мобільний — не «стиснутий десктоп»: перебудуй сітку в одну колонку, збільш тап-таргети (≥44px).
- Перевір на 360–390px ширини; нічого не вилазить, текст читабельний (≥16px base).
- Видимий фокус клавіатури (`:focus-visible`), працює навігація табом.
- Зображення адаптивні, з `width`/`height` (без стрибків layout).
- Темна/світла версія — якщо є, узгодь контраст в обох.

---

## Фінальний чекліст лендінгу

- [ ] Визначено суб'єкт, аудиторію і **одну** ціль сторінки
- [ ] Hero за 3 сек пояснює, що це і навіщо; є головний CTA
- [ ] Один акцентний колір, дозовано (правило 10%), решта — нейтральна база
- [ ] Палітра з ролями (фон/поверхня/текст/акцент), контраст ≥ AA
- [ ] Пара шрифтів: display + body, чітка типо-шкала й ієрархія
- [ ] Система відступів 4/8px, узгоджений вертикальний ритм секцій
- [ ] Один сигнатурний елемент; решта тиха й дисциплінована
- [ ] Рух доречний і тонкий; `prefers-reduced-motion` враховано
- [ ] CTA-текст = конкретна дія, повторений угорі й унизу
- [ ] Адаптив до ~360px, видимий фокус, тап-таргети ≥44px
- [ ] Дизайн **не** скочується в один із трьох ші-дефолтів
