# SEO Rules for AI

Правила та приклади, яких ші має дотримуватися при генерації або рефакторингу веб-коду й контенту. Мета — щоб згенерований результат був технічно коректним для пошукових систем, доступним (a11y) і швидким.

> Формат правил: `✅ роби так` / `❌ не роби так`. Якщо правило конфліктує з вимогами користувача — пріоритет у користувача, але познач компроміс.

---

## 0. Базові принципи

1. **Семантика важливіша за візуал.** Спершу правильний HTML, потім стилі.
2. **Одна сторінка — одна тема.** Один `<h1>`, один основний ключ, один canonical.
3. **Не дублюй контент.** Однаковий текст на різних URL → canonical або редірект.
4. **Швидкість = ранжування.** Стеж за Core Web Vitals (LCP, INP, CLS).
5. **Контент для людей, оптимізація для ботів.** Не наповнюй ключами штучно.
6. **Кожне правило перевіряй прикладом** з реального згенерованого коду, а не абстрактно.

---

## 1. Семантичний HTML

✅ Використовуй теги за призначенням:

```html
<header>…</header>
<nav aria-label="Головне меню">…</nav>
<main>
  <article>
    <h1>Заголовок сторінки</h1>
    <section>…</section>
  </article>
  <aside>…</aside>
</main>
<footer>…</footer>
```

❌ Не будуй структуру на `<div>`:

```html
<div class="header"></div>
<div class="content">
  <div class="title">Заголовок</div>
</div>
```

**Правила:**
- Рівно один `<h1>` на сторінку.
- Ієрархія заголовків без пропусків: `h1 → h2 → h3`, а не `h1 → h4`.
- Інтерактив — це `<button>` / `<a>`, а не `<div onclick>`.
- Списки — `<ul>`/`<ol>`, а не набір `<div>`.

---

## 2. `<title>` та meta description

✅ Правильно:

```html
<title>Купити онігірі у Львові — доставка за передзамовленням | Onigiri</title>
<meta name="description" content="Свіжі онігірі ручної роботи у Львові. Передзамовлення на день наперед, доставка по місту. Від 45 грн за штуку.">
```

**Правила `<title>`:**
- Довжина ~50–60 символів (щоб не обрізалося у видачі).
- Головний ключ ближче до початку.
- Унікальний для кожної сторінки.
- Формат: `Основне — уточнення | Бренд`.

**Правила description:**
- ~140–160 символів.
- Містить ключ + заклик/вигоду, але читається природно.
- Унікальний. Не дублюй `<title>`.
- Це не фактор ранжування напряму, але впливає на CTR.

❌ Не роби:
- Однаковий `<title>` на всіх сторінках.
- `<title>Головна</title>`, `<title>Untitled</title>`.
- Description набитий ключами через кому.

---

## 3. Canonical, robots, індексація

```html
<link rel="canonical" href="https://example.com/blog/seo-guide">
<meta name="robots" content="index, follow">
```

**Правила:**
- Canonical — абсолютний URL, вказує на «головну» версію сторінки.
- Сторінки з параметрами (`?sort=`, `?utm=`) → canonical на чисту версію.
- Технічні/службові сторінки (кошик, дякуємо, адмінка) → `noindex, follow`.
- Не став `noindex` разом із canonical на ту саму сторінку — суперечливий сигнал.

`robots.txt` (мінімум):

```
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /api/

Sitemap: https://example.com/sitemap.xml
```

## 4. Open Graph та Twitter Cards

Для коректного вигляду посилань у соцмережах і месенджерах:

```html
<meta property="og:title" content="Купити онігірі у Львові">
<meta property="og:description" content="Свіжі онігірі ручної роботи, доставка по місту.">
<meta property="og:image" content="https://example.com/og/onigiri.jpg">
<meta property="og:url" content="https://example.com/onigiri">
<meta property="og:type" content="website">
<meta name="twitter:card" content="summary_large_image">
```

**Правила:**
- `og:image` — абсолютний URL, рекомендований розмір 1200×630.
- Кожна ключова сторінка має власні OG-теги.

---

## 5. Структуровані дані (JSON-LD)

Використовуй schema.org через JSON-LD у `<head>` або кінці `<body>`.

Приклад для статті:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Повний гайд по SEO для фронтенду",
  "author": { "@type": "Person", "name": "Vlad" },
  "datePublished": "2026-08-20",
  "image": "https://example.com/img/seo-guide.jpg"
}
</script>
```

**Правила:**
- Розмітка має описувати реальний контент сторінки (не фейкові дані).
- Обирай правильний `@type`: `Product`, `Article`, `BreadcrumbList`, `FAQPage`, `LocalBusiness`, `Organization`.
- Перевіряй через Rich Results Test.

❌ Не додавай `FAQPage`, якщо на сторінці немає видимого FAQ — це порушення правил Google.

---

## 6. Зображення

✅ Правильно:

```html
<img
  src="/img/onigiri.webp"
  alt="Онігірі з лососем на дерев'яній дошці"
  width="800"
  height="600"
  loading="lazy"
  decoding="async">
```

**Правила:**
- `alt` — описовий і осмислений; для декоративних — `alt=""`.
- Завжди задавай `width`/`height` (запобігає CLS).
- Формати: WebP/AVIF замість JPEG/PNG де можливо.
- `loading="lazy"` для зображень нижче першого екрана.
- **Не** лінивь LCP-зображення (головне зображення першого екрана) — навпаки, `loading="eager"` / `fetchpriority="high"`.

---

## 7. URL та внутрішні посилання

**URL:**
- Короткі, читабельні, з ключем: `/blog/seo-guide`, а не `/blog?id=482`.
- Малі літери, слова через дефіс, без `_` та кирилиці в слагах.
- Стабільні: змінив URL → постав 301-редірект зі старого.

**Посилання:**

```html
<a href="/onigiri">Меню онігірі</a>          <!-- ✅ описовий текст -->
<a href="/onigiri">тут</a>                    <!-- ❌ неінформативний анкор -->
```

- Анкор описує ціль посилання, а не «читати далі»/«тут».
- Зовнішні посилання, яким не довіряєш: `rel="nofollow"` / `noopener`.
- Не залишай биті посилання (404 у внутрішньому лінкуванні).

---

## 8. Продуктивність / Core Web Vitals

Цільові значення:

| Метрика | Добре | Що впливає |
|---|---|---|
| **LCP** | < 2.5 с | розмір/пріоритет головного зображення, TTFB |
| **INP** | < 200 мс | важкий JS, довгі задачі в main thread |
| **CLS** | < 0.1 | розміри зображень, шрифти, вставки |

**Правила:**
- Критичний CSS інлайном, решта — асинхронно.
- Шрифти: `font-display: swap`, `preload` для головного шрифта.
- Не блокуй рендер зайвим JS; ліниво вантаж усе некритичне.
- Мінімізуй сторонні скрипти (аналітика, віджети).

---

## 9. Мобільність та доступність

- Адаптивний layout, `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Тап-таргети ≥ 44px, читабельний розмір шрифту (≥ 16px базово).
- Контраст тексту відповідає WCAG AA.
- Доступність і SEO йдуть разом: `alt`, `aria-label`, семантика, порядок фокуса.

---

## 10. Багатомовність (hreflang)

Якщо є версії різними мовами:

```html
<link rel="alternate" hreflang="uk" href="https://example.com/uk/">
<link rel="alternate" hreflang="en" href="https://example.com/en/">
<link rel="alternate" hreflang="x-default" href="https://example.com/">
```

- Кожна версія посилається на всі інші + на себе.
- `x-default` — для мовно-нейтральної/дефолтної версії.

---

## 11. Контентне SEO

**Правила:**
- Один основний ключ + кілька семантично близьких на сторінку.
- Ключ природно у: `<title>`, `<h1>`, першому абзаці, одному з підзаголовків.
- **Без** перенасичення ключами (keyword stuffing) — текст має читатися для людини.
- Структуруй: короткі абзаци, підзаголовки, списки, таблиці.
- Перші 100 слів дають зрозуміти тему сторінки.
- Унікальний контент; не копіюй чужий чи власний з інших сторінок.

❌ Погано:

> Купити онігірі Львів онігірі дешево онігірі доставка онігірі замовити онігірі...

✅ Добре:

> Готуємо онігірі щоранку у Львові й доставляємо за передзамовленням. Обирайте начинку, оформлюйте замовлення на день наперед — привеземо свіже.

## 12. Angular-специфіка (SSR / рендеринг)

Для SEO важливо, щоб бот бачив контент у HTML, а не порожній `<app-root>`.

- Використовуй **SSR / prerendering** (`@angular/ssr`, Angular Universal) для індексованих сторінок — CSR-only погано індексується.
- Мета-теги задавай динамічно через сервіси, а не хардкодь в `index.html`:

```ts
import { Title, Meta } from '@angular/platform-browser';

constructor(private title: Title, private meta: Meta) {}

ngOnInit(): void {
  this.title.setTitle('Купити онігірі у Львові | Onigiri');
  this.meta.updateTag({
    name: 'description',
    content: 'Свіжі онігірі ручної роботи, доставка по Львову.',
  });
  this.meta.updateTag({ rel: 'canonical', href: 'https://example.com/onigiri' });
}
```

- Генеруй `sitemap.xml` та `robots.txt` у білді або на сервері.
- Уникай контенту, що з'являється лише після кліку/скролу, якщо він важливий для індексації.
- Ліниве завантаження роутів (`loadComponent`) — ок для швидкості, але переконайся, що SSR віддає готовий HTML.

## Фінальний чеклист для сторінки

- [ ] Один `<h1>`, коректна ієрархія заголовків
- [ ] Унікальні `<title>` (≤60) і description (≤160)
- [ ] Canonical на правильний URL
- [ ] OG / Twitter теги з абсолютним `og:image`
- [ ] JSON-LD відповідає контенту
- [ ] У зображень є `alt`, `width`, `height`, lazy де треба
- [ ] Семантичні теги, доступні посилання з описовими анкорами
- [ ] LCP < 2.5с, CLS < 0.1, INP < 200мс
- [ ] Адаптив + viewport meta
- [ ] hreflang, якщо мов кілька
- [ ] Немає keyword stuffing, контент унікальний
- [ ] (Angular) SSR/prerender віддає готовий HTML з мета-тегами
